# 防衛施設ウォッチ

自衛隊基地・防衛施設の整備と、防衛に関わる建築土木だけを追う個人用ニュースサイト。
GitHub Actions が1日3回（日本時間 7時 / 12時 / 19時）動いて、収集・要約・ページ生成まで自動で行う。

```
news/config.mjs      追うテーマと情報源。ふだん触るのはここだけ
news/build.mjs       収集 → 要約 → HTML生成をつなぐ入口
news/preview.mjs     ダミーデータで見た目だけ確認する
news/tools/          地図データの生成器（普段は動かさない）
news/selftest.mjs    外部ネットワーク不要の自己テスト
news/lib/            フィード解析・本文抽出・要約・集計・HTML生成
data/archive.json    集めた記事の蓄積（コミットされる）
docs/                生成されたサイト（コミットされる）
```

## 画面

HUD（ヘッドアップディスプレイ）風の一枚もの。上から順に、日本地図、計器の列
（直近の件数・新着・要注目・媒体数・蓄積数）、本日の要点、情報源の稼働ゲージ、
記事量の推移、カテゴリ別の内訳、頻出する語、そして要約付きの記事一覧が並ぶ。

### 日本地図

記事のある地方にピンが立つ。件数はピンの中の数字で、要注目の記事がある地方は
琥珀色になって輪が広がる。ピンか右の一覧を押すとその地方の記事だけに絞り込め、
もう一度押すと解除される。

どの地方の話かは `news/config.mjs` の `regionKeywords` で判定している。
駐屯地・基地名などその土地でしか出ない語（`sites`）は重み3、都道府県や地方名
（`areas`）は重み1。重みを分けているのは、防衛省の所在地として「東京」が出てくる
だけの記事が関東の記事にならないようにするため。同点なら地方を決めず「全国・不明」
に置く。取り違えたピンを立てるより、そのほうがまだいい。

追う施設が増えたら `sites` に足す。ここが一番効く。

地図そのものは MapSVG の日本地図（CC BY 4.0）を、npm の `@svg-maps/japan` 経由で
取り込み、47都道府県を9地方に結合したもの。生成物は `news/lib/japan-map.mjs` に
書き出してコミットしてあるので、実行時に依存は無い。地方の区切りを変えるときだけ
`news/tools/build-map.mjs` を直して `npm run news:map` を実行する。

意匠として暗い面に決め打ちしてあり、明暗の切り替えは持たない。
`prefers-reduced-motion` を有効にしているブラウザでは、立ち上がりの動きと
流れる見出しは止まる。

グラフの色は6カテゴリぶんを色覚多様性の基準で検証した並び順で固定してある。
カテゴリを増減させたときは `news/lib/render.mjs` の `SERIES` を確認すること。
色は必ずカテゴリ名と一緒に出しており、色だけで意味を運ばせていない。

## 公開の設定（最初に1回だけ）

リポジトリの **Settings → Pages** で、どちらかを選ぶ。

- **Deploy from a branch**：ブランチを選び、フォルダに `/docs` を指定する。追加の設定は要らない。
- **GitHub Actions**：ワークフロー内の `deploy` ジョブがそのまま公開まで行う。

要約に Claude を使う場合は、**Settings → Secrets and variables → Actions** に
`ANTHROPIC_API_KEY` を登録する。未登録でもサイトは動くが、要約は本文からの機械的な
抜き出しに切り替わる（下記「要約の作られ方」）。

## 追う内容を変える

`news/config.mjs` を編集する。

### キーワード

このサイトが拾うのは「防衛」×「施設・建築土木」の交差点であって、防衛ニュース全般でも
建設ニュース全般でもない。判定はこの形になっている。

| 条件 | 結果 |
|---|---|
| `topic` の語が1つ当たる | 採用（`馬毛島`、`辺野古`、`火薬庫` など、1語で文脈が決まるもの） |
| `defense` と `facility` が両方当たる | 採用（例：`沖縄防衛局` × `入札`） |
| それ以外 | 不採用 |

片方だけで通すと「自衛隊が離島で訓練」や「歩道橋の架け替えが着工」まで入ってきて、
絞る意味がなくなる。追いたい語が漏れていたら、性質に合うリストに足す。

### 情報源

`sources` に足す。`urls` は候補の配列で、上から順に試して最初に読めたものを使う。
フィードの場所が変わっても候補を並べておけば拾い直せる。

```js
{
  id: 'example',
  name: '媒体名',
  kind: 'rss',
  hint: '専門紙',                     // 表示用のラベル。省略可
  urls: ['https://example.com/feed', 'https://example.com/rss'],
}
```

キーワードで横断的に探したいだけなら `googleNews('検索語')` を足す方が早い。

### カテゴリ

`categories` を編集する。`id` は要約時の分類に使われるので、意味の重なりが少ない粒度で切る。
増減させると、要約モデルに渡す選択肢とページ上の絞り込みが自動で追随する。

## 要約の作られ方

`ANTHROPIC_API_KEY` があれば Claude（`claude-opus-5`）が記事本文から日本語3行の要約、
カテゴリ、注目度を作る。出力は JSON スキーマで形を固定してあるので、崩れた応答で
生成が止まることはない。

鍵が無い、あるいは API 呼び出しに失敗した記事は、本文から要点らしい3文を機械的に
抜き出した簡易要約に落ちる。**ページ下部に、どちらで作られたかが表示される。**

一度要約した記事は作り直さない。実行のたびに費用がかさむのを避けるためで、
`data/archive.json` を消せば作り直される。

### 費用の目安

新着記事だけを要約するので、定常状態で1日あたり数十円〜200円程度。初回は蓄積が無いぶん
高くつく。抑えたいときの調整箇所は3つ。

- `site.maxArticlesPerRun` … 1回に本文取得と要約に回す記事数の上限
- `.github/workflows/news.yml` の `cron` … 実行回数
- `news/lib/summarize.mjs` の `MODEL` … 別のモデルに変える

## 手元で動かす

```bash
npm ci
npm run news:test      # 自己テスト（ネットワーク不要）
npm run news:dry       # 収集と要約だけ試す。ファイルは書かない
npm run news:build     # docs/ と data/ を実際に生成する
npm run news:preview   # ダミーデータで見た目だけ確認する
node news/build.mjs --no-llm   # Claude を使わずに組む
npm run news:map       # 地図データを作り直す（地方の区切りを変えたときだけ）
```

`news:preview` は記事を取りに行かず、作り物のデータで `dist-news-preview/index.html`
を書き出す。見た目をいじるときはこれが速い。生成物には「表示サンプル」の帯が出る
ので、実データと取り違えることはない。

## Google ニュースのリンクについて

このサイトの記事の多くは Google ニュースの検索フィード経由で見つかる。ところが
その `link` は news.google.com のリダイレクタで、元記事のURLがそのままでは分からない。
診断（`npm run news:probe`）で確かめたところ、

- HTTP のリダイレクトは起きない（200 で 580KB の Angular 製ページが返る）
- HTML の中に元記事のURLは無い（外部ホストは解析・CDN のみ）
- 記事IDの base64 にもURLは埋まっていない
- 飛ばしているのは `window.location` による JavaScript の遷移

つまり HTTP だけでは解決できない。そこで Playwright の Chromium で実際に開き、
飛んだ先を元記事URLとして採る（`news/lib/resolve.mjs`）。

ブラウザが無い環境では解決を諦め、その記事は「見出しのみ」として扱う。要約は
見出しから言えることだけになり、ページ上にもその印が出る。

## うまく動かないとき

生成されたページの下部と、GitHub Actions の実行サマリに、情報源ごとの取得結果が出る。

- **特定の情報源が × のまま** … その媒体がフィードをやめたか、場所を変えた可能性が高い。
  `urls` に候補を足すか、行ごと消す。
- **全部 × でワークフローが赤い** … 回線か、まとめてブロックされている。実行サマリに理由が出る。
- **記事が少なすぎる** … キーワードが厳しすぎる。`topic` に語を足すのが一番効く。
- **関係ない記事が混ざる** … `defense` か `facility` の語が広すぎる。狭めるか `exclude` に足す。
- **ピンが立つ地方が違う** … `regionKeywords` の `areas` に広すぎる語が入っている。
  その土地でしか出ない語を `sites` に足すほうが早い。
- **記事があるのにピンが立たない** … 地名が拾えていない。`sites` に施設名を足す。
- **「見出しのみ」の記事ばかりになる** … 元URLの解決が効いていない。実行ログの
  「元URLの解決: 有効/無効」を見る。無効なら Chromium が用意できていない。
- **情報源の候補を探したい** … `npm run news:probe` を走らせる。候補URLをまとめて
  試し、Google ニュースのリンク解決も調べる。専用のワークフローからも回せる。
