# ドローン飛行申請SaaS ― プロジェクト・プロンプト（まとめ）

> これまでの打ち合わせ・依頼内容を1本に集約したもの。新しいチャットの起点や、仕様の共有・引き継ぎにそのまま使えます。

---

## 1. 目的・背景

ドローンの飛行申請まわりの業務（飛行計画づくり、点検、記録、飛行日誌）を簡略化する**Webソフト＋モバイルアプリ**をつくる。
現場が圏外になることも多いので、将来的にはオフライン入力＋後同期を想定。自社（NHCT）運用に加え、**他社にも提供するSaaS製品**にする。

## 2. 確定スコープ

- **構成**：Web管理画面＋モバイルアプリを、1つのレスポンシブWeb/PWAで提供（単一アプリ）。
- **DIPS 2.0 連携**：公式の外部APIは原則ないため連携前提にしない。「**飛行日誌の独立管理**」を軸にする。
- **提供形態**：マルチテナント（組織ごとにデータを分離）のSaaS。
- **法令適合**：航空法の記録義務が前提。国交省 **様式1〜3**（飛行記録／日常点検記録／点検整備記録）にデータモデルを合わせる。

## 3. 機能要件（これまでの依頼を集約）

### 3.1 点検（飛行前／飛行後）
- 機体の**機種ごとに点検項目が異なる**ため、機種マスタに点検テンプレートを持たせ、機体を選ぶと点検フォームを自動生成する。
- テンプレートは **標準項目（国交省9項目）＋機種固有項目＋組織固有項目** の3スコープを合成。
- 実運用中のGoogleフォーム（SOTEN機/ACSL製）に合わせ、**選択肢式**の点検にする。
  - 1つだけ選択（排他）＋「その他」自由記入。
  - 送信すると**履歴がスプレッドシート的に残る**（アプリ内の一覧＋CSV出力。GoogleシートAPI連携はしない）。
- メイン機は **DJI Air 3S / DJI Matrice 4T**。カメラ一体型に合わせた点検テンプレも用意。

### 3.2 飛行計画＋落下計算（統合地図ツール）
- 単独の計算ページではなく、**地図でルートを作りながら落下予測範囲を図示**する統合ツール。
  - 地図をクリックして **離陸→撮影（複数可）→着陸** のピンを立て、ルートを描く。
  - 各地点に **落下予測範囲**（国交省式 `D = R × f`）の円を描画。**各地点の飛行高度に連動**して円の大きさが変わる。
  - **平面図（道路・建物が入った実地図）＋立面図（高度プロファイル）** を表示。
  - **飛行高度の一括変更**（トグルON＋数値で、離着陸を除く全撮影点を一括設定）。
  - **最高高度（制限）**入力→撮影1点目に自動反映＋立面図に制限ラインと超過警告。
  - **日付を選ぶと日の出・日没を自動計算**（離陸地点の緯度経度・JST）。夜間飛行判断用。
  - **離陸地点の座標コピー**ボタン（福岡空港 高さ制限回答システムに手入力する運用）。
- **飛行計画を保存**でき、**保存した計画と点検実施をリンク**できる（計画→点検、計画詳細に紐づく点検一覧）。

### 3.3 飛行禁止・要注意区域の考慮 ★最新の改善
- **空港周辺（制限表面＝許可・承認が必要）・病院周辺（ドクターヘリ等で要注意）**を地図に重ねる。
- 離発着点や**落下予測範囲の円がその区域に重なったら警告**を出す。保存した計画の詳細でも再表示。
- データ：①主要空港を内蔵（常時表示）②「周辺を検索」でOpenStreetMapから病院・空港・ヘリポートを取得。
- あくまで**計画補助の目安**。DID（人口集中地区）・150m以上・緊急用務空域などは含まず、最終確認はDIPS/地理院地図/各空港の高さ回答システムで、と明示。

### 3.4 機体・機種マスタ
- **市販25機種のイラスト（自作PNG）をアプリ同梱**。機体登録で機種を選ぶと画像が自動表示（ユーザーがアップロードするのではなく、こちらが用意した画像を出す）。
- 機体中心の**レクサスアプリ風ダッシュボード**（ダークなコントロールパネル、機体セレクタ、機種連動の立体イラスト、総飛行時間/点検回数、飛行計画/点検実施/飛行記録/点検履歴のアクション、飛行前点検の状況表示）。

### 3.5 飛行記録・飛行日誌
- 様式1の飛行記録（機体・日付・操縦者・概要・離着陸場所/時刻・飛行時間自動算出・確認者・安全影響事項・不具合）。保存で機体の総飛行時間に加算。
- 飛行日誌のPDF出力（様式1〜3）は今後の候補。

## 4. 技術構成

- **フロント**：Next.js 16（App Router / React 19 / Tailwind 4 / Turbopack）。`web/` 配下。
  - Next.js 16 の破壊的変更に注意（`middleware`→`proxy.ts`／`export function proxy` など。AGENTS.md参照）。
- **バックエンド**：Supabase（PostgreSQL / Auth / Storage / RLSでマルチテナント分離）。
  - 認証：メール＋パスワード。組織作成はRPC（SECURITY DEFINER）。
- **地図**：Leaflet 1.9 ＋ OpenStreetMap（APIキー不要）。SSR回避のためdynamic import。
- **画像最適化**：sharp。**外部連携や公的サイトのスクレイピングはしない**（手入力→自動反映の形）。
