# 投資リサーチ・ダッシュボード（`research/`）

銘柄コードを入れると、株価・チャート・テクニカル条件・IR・ニュース・決算・財務を1画面で確認できる
Next.js アプリ。サイトは売買を推奨しない。テクニカル条件は「ゴールデンクロス発生」「RSI 30未満」のような
客観的な事実として示し、過去データとの比較にはサンプル数と「将来を保証しない」旨を必ず添える。

設計の全体像（現状分析・DB・API・画面・実装順序）は [`docs/PLAN.md`](docs/PLAN.md)。

## 動かす

```bash
cd research
npm install          # postinstall で Prisma Client も生成される
npm run dev          # http://localhost:3000
```

API キーも DB も無しで、モックデータ（画面上に「サンプルデータ」と表示）で一通り動く。

### 実データで動かす（全銘柄を検索できる版）

`DATA_SOURCE=yahoo` で、株価と指数を Yahoo Finance から取得する（遅延あり）。
日本株は東証の全上場銘柄（`src/data/jp-stocks.json`、JPX の一覧から GitHub Actions が月1回更新）を
日本語名・コードで検索でき、米国株などは英字・ティッカーで Yahoo の検索から見つかる。
IR・ニュース・財務・予定は提供元が未接続のため「未接続」と表示する（作り物は出さない）。

Vercel に置くと、`DATA_SOURCE` を設定しなくても自動で実データになる。

1. vercel.com に GitHub アカウントでログインし「Add New → Project」
2. `2kasa06/2kasa` を Import
3. 「Root Directory」を `research` にして Deploy

Yahoo Finance の公開エンドポイントは公式に保証された API ではない。個人の閲覧用にとどめ、
データを再配布しないこと。本格運用ではライセンスのある提供元（J-Quants など）に差し替える。
例: http://localhost:3000/stocks/7203

| コマンド | 内容 |
|---|---|
| `npm run dev` / `build` / `start` | 開発サーバ / 本番ビルド / 本番起動 |
| `npm test` | 指標・シグナル・過去検証・ニュースの束ね・IR 判定のテスト（vitest） |
| `npm run typecheck` / `lint` | 型検査 / ESLint |
| `npm run db:migrate` | マイグレーション（`DATABASE_URL` が必要） |
| `npm run db:seed` | モックデータを DB に投入（何度流しても重複しない） |

### サーバ無しの静的版（GitHub Pages）

```bash
npm run build:static   # docs/research/ に書き出す（配信パス /2kasa/research/）
```

API を使わず、ビルド時に書き出した株価の JSON からチャートの指標とシグナルをブラウザで計算する。
公開先: https://2kasa06.github.io/2kasa/research/ 。データはビルドした日の時点で固定される。

### DB を使う場合

```bash
docker compose up -d                 # PostgreSQL 16 と Redis
cp .env.example .env                 # Prisma CLI 用
cp .env.example .env.local           # Next.js 用
npm run db:migrate && npm run db:seed
```

`/api/health` で DB 接続とデータ提供元の状態を確認できる。

## 構成

```
src/app/                    画面と API（App Router）
  page.tsx                  トップ（市場サマリー・市場環境・銘柄一覧）
  stocks/[code]/page.tsx    銘柄ページ
  api/…                     検索・株価・シグナル・市場・ヘルスチェック
src/components/             UI（ui/ は shadcn/ui 方式の基本部品）
src/lib/
  providers/                データ取得層（インターフェースと mock 実装）
  technical/                指標・シグナル検出・過去検証（依存なしの TypeScript）
  analysis/                 ニュースの束ね・IR の重要度判定
  services/                 画面用にデータを組み立てる層
  api.ts logger.ts cache.ts レート制限・ログ・キャッシュ
prisma/                     スキーマ（19テーブル）・マイグレーション・シード
```

### データ取得層

UI は `getProviders()` 越しにしかデータに触れない。提供元を足すときは
`src/lib/providers/types.ts` のインターフェースを実装し、`providers/index.ts` の `DATA_SOURCE` 分岐に加える。
戻り値は必ず `DataResult<T>`（`ok` / `empty` / `error` ＋出所と時点）で、失敗を 0 や前回値として流さない。
画面側は `error` なら「データ取得失敗」、`empty` なら「データなし」を出す。

実データを組み込む前に、提供元の利用規約・API 規約・再配布条件を確認すること。
スクレイピングを禁じているサイトは使わない。

## 実装済みの機能（PHASE 1〜3）

- **トップ**: 13指標のカード（現在値・前日比・更新日時）、市場環境（事実のみ。AI 欄は別枠で明示）、銘柄一覧と検出中の条件
- **検索**: コード・名称・英語名・ティッカー。`/stocks/toyota` のような名称の URL も1件に絞れれば該当銘柄へ移動
- **銘柄ページ**（PC は指示書40、スマホは45の順）
  - 基本情報・株価・時価総額・PER・PBR・配当利回り・EPS
  - **現在の状況サマリー**（テクニカル・IR・ニュース・決算の要点と、成立中の条件の件数）
  - チャート: 1日〜全期間、ローソク足、SMA 5/25/75/200、EMA 12/26、ボリンジャー、一目均衡表、VWAP、出来高（急増の印付き）、RSI、MACD、シグナルのマーカー（クリックで発生日・条件・発生時と現在の数値）
  - シグナル: 移動平均のクロス、各移動平均線の上抜け・下抜け、RSI 30未満/70超、MACD のクロス・ゼロライン・ヒストグラム拡大縮小、ボリンジャーの ±2σ・バンドウォーク・スクイーズ・エクスパンション、出来高急増。条件の強さ（高・中・低と理由）、複数同時発生の件数、履歴、過去の同条件の1・5・10・20営業日後（サンプル数・平均・中央値・最大・最小・上昇した割合、20回未満は「参考値」）
  - IR: 重要度（最重要・重要・通常）と分類根拠、3行要約、原文リンク
  - ニュース: 同じ出来事の報道を束ねて「関連報道 n件」、論調は「AIによる分類」と明示し、規制・政治などは「中立/要確認」
  - 決算: 前年同期比・前四半期比・市場予想との差・通期会社予想と進捗率・営業利益率の変化
  - 財務: 損益・成長率・ROE/ROA/自己資本比率・有利子負債・現金・FCF・配当・配当性向・自社株買い・総還元性向、8指標の推移グラフ（通期/四半期・期間切替）
  - 今後60日のイベント
- 全欄に「提供元・データの時点・最終更新」を表示。モックは「サンプルデータ」と明示
- ライト/ダーク切替、スマホ対応、銘柄ページごとの SEO タイトル、API のレート制限・入力検証・内部エラーの秘匿、構造化ログ

## まだのもの（PHASE 4〜7）

市場情勢の AI 要約、マクロ指標、業界分析・同業比較、バリュエーションの過去レンジ、イベントカレンダー表示、
AI リサーチ（出典付き）、ウォッチリスト（認証）、通知、スクリーナー、急騰・急落と出来高異常の市場横断検出、
実データの提供元。

## 注意

- 祝日はモックでは考慮していない（土日のみ除外）。
- 「全期間」のチャートは日足10年分で約1.8MB。本番はリバースプロキシ・CDN で gzip を掛ける前提。
- テクニカル条件の色（緑・赤・黄）は「一般に上昇・下落どちらの動きと結び付けて語られる条件か」の分類で、
  売買の判断ではない。画面の凡例にも文字で出している。
